# Huly 群聊 @Agent 文档评审实施计划

## 1. 目标与边界

在本地 Huly 源码的 Chunter「聊天 → 频道」中实现群聊文档评审。频道成员通过结构化 `@技术评估Agent`、`@方案Agent`、`@合同Agent` 依次生成和交接文档；人工下载、修改、上传定稿后才进入下一阶段。本次范围包含本地开发、独立 Docker 测试配置、自动检查和人工验收准备；服务器更新待本地验收通过后另行安排。

首版支持 DOCX、文字 PDF、Markdown 消息附件作为输入，输出 DOCX 与 Markdown 线程附件；不包含扫描件 OCR、Excel、在线 Word 编辑、自动签署或对外发送。模型服务商、模型名、地址和密钥由使用者填写本地 API 配置文件。

## 2. 交互规则

- 一项需求对应一个现有 Chunter 原生线程，同频道可并行多项需求；需求根消息保存名称。
- 未选中需求时，带附件的 `@技术评估Agent` 先要求命名；确认后建立需求并选中，取消则保留文字和附件草稿。未选中时调用方案或合同 Agent 会提示先选择已有需求。
- 输入框上方始终显示「当前需求：客户 A［切换］［退出需求］」；没有选择时显示「当前需求：未选择，发送到频道普通聊天［选择需求］」。选择按用户、工作区、频道保存，刷新后恢复并重新校验权限；失效时阻止发送，不静默转普通聊天。
- 选中后文字、附件和 `@Agent` 发送到该需求线程。主聊天区按时间聚合普通消息和需求线程消息，需求消息显示名称标记，使用原消息 ID 去重，不复制回复。点击标记即可切换需求。
- 上传和发送在开始时冻结需求目标；切换不会移动上传中的文件。Agent 回复绑定原需求。每次交接必须有一份 DOCX 或 Markdown 定稿，记录发送者、文件哈希和确认时间。
- 同阶段可带修改意见重跑并保留历史。上游变更会使下游重新进入待确认。多个 Agent 同时被提及时要求选择一个；机器人消息、普通聊天和纯文本伪造提及不启动评审。

## 3. 源码实现

### Chunter

在 `ChatMessage` 和模型中增加仅根消息使用的 `reviewDemandTitle`。增加需求上下文查询、创建、切换、退出、消息提交前检查和草稿键隔离；ChannelDataProvider 的元数据、尾部订阅、历史分页都按同一范围查询频道消息与已建立需求线程，保留普通线程语义。历史消息缺少字段时继续作为普通消息。

### `services/agent-review`

服务以三个独立 Huly 机器人账号连接测试工作区，每 5 秒轮询启用频道，启动和重连补扫；解析真实结构化人员引用。SQLite 保存扫描游标、任务、不可变输入快照及哈希、运行版本、人工确认、输出附件和错误。同一需求串行，总并发默认 2，可配置。每次运行建立隔离 Pi 会话，只暴露当前输入、允许参考资料和结构化草稿提交工具，关闭默认 shell、任意读写和扩展自动发现；Huly 发布和重试由服务控制，发布重试复用已有输出。

运行状态包括排队、执行、待人工确认、失败和完成。技术评估完成后才可交接方案，方案完成后才可交接合同；合同定稿并发送「@合同Agent 确认定稿」后标记评审完成。编辑已发消息不自动重跑，重复扫描不重复发布。

### 文档处理与参考资料

只读加载以下材料并记录哈希：`D:\零律\企业内部知识库问答系统技术评估案例-v1.0.docx`、新建的 `方案编写参考.md`、`D:\零律\合同 skill\software-development-contract\SKILL.md` 及其 `references\clause-decisions.md`。案例只提供结构和方法，不能继承其中工期、人数、指标或技术选型；合同未知主体、金额、付款、期限等保留待填写项。解析 DOCX 正文和表格并提示修订/批注，提取文字 PDF，拒绝扫描件，Markdown 直接解析；Markdown 为源稿并确定性生成 DOCX，人工检查分页、表格、字体和签署区。

## 4. 配置与本地环境

提供 `api.config.example.json` 和被忽略的 `api.config.local.json`，包含供应商、接口类型、地址、模型、Key、超时和输出限制占位项；运行配置包含 Huly 地址、工作区、启用频道、三个账号、参考文件白名单、数据目录和并发限制。真实凭据不进 Git 或日志。提供独立容器、网络、端口和数据卷的本地 Docker 配置，记录源码提交和镜像版本，禁止混用不同 Huly 组件版本。

## 5. 实施阶段与完成标准

| 阶段 | 产物与完成标准 |
|---|---|
| A 本地环境 | 独立 Docker、测试工作区/频道/账号和可登录、提及、附件收发记录。 |
| B 需求交互 | 命名、当前需求栏、切换退出、草稿隔离、主聊天聚合和名称标记；两项需求可交替讨论。 |
| C 技术评估 | Pi 接入、附件解析、参考案例、任务持久化、文档生成、重启恢复和重跑版本。 |
| D 方案与合同 | 方案规范、两次人工定稿交接、合同 skill、商务待填写项和完成确认。 |
| E 测试验收 | 自动/静态检查、浏览器联调、文档检查、缺陷修复和人工验收清单。 |

开发分支为 `codex/huly-chat-agents`。按项目 `AGENTS.md` 不自动运行构建；提供用户可复制的构建和启动步骤，测试记录区分已执行、失败和待人工执行。服务器更新不在本计划内。

## 6. 验收场景

覆盖首次带附件命名及取消、当前需求栏滚动/切换/刷新、客户 A/B 交替发送、多成员共同选择、主聊天分页和实时标记、草稿及上传中切换、普通/伪造/机器人提及、缺少定稿或跨阶段提及、修改重跑及上游失效、断线重启重复扫描、模型配置错误/超时/不支持文件、权限隔离、DOCX/PDF/Markdown 解析、三阶段来源可核对和原有普通聊天/附件/私信/普通线程回归。人工验收至少使用两项测试需求和两名成员，并接入用户填写的真实模型 API；模拟响应只验证流程。

## 7. 交付物

源码、本文档、配置示例、方案编写参考、独立本地环境操作说明、机器人和人工交接指南、测试结果、人工验收清单。服务器部署在验收通过后单独安排。
